# 🌊 digiwallsys — v1.7.0

> *Name: Compass*

**Status:** Release

---

## 📖 Overview

**Compass** adds a real Analytics dashboard, computed from live transaction and
payment-request data rather than placeholder numbers: money in vs. out, a spend
breakdown, and a monthly spending lock built on the existing spending-alert preference.

## 🎯 Objectives

- Give users an at-a-glance view of this month's money in, money out, and balance.
- Break spending down by channel using data the ledger already records.
- Surface the existing spending-alert threshold as a visible monthly "lock" progress bar.
- Ship on both mobile and web from the Lantern/Marina shell with no new backend routes.

## ✨ Production Scope & Enhancements

### 📊 Analytics screen

- New `AnalyticsScreen.js`, reachable from the Home tile grid and the web sidebar.
- `DonutChart` / `ChartLegend` components built on `react-native-svg` (no new chart
  dependency) rendering:
  - **Balance vs. spent this month** — spent, balance, and received, from
    `/api/transactions/history` aggregated client-side over the current month.
  - **Where this month's spend went** — "Direct transfers" (`/transactions/send`) vs.
    "Requests & QR payments" (accepted `payment_requests`), matched by `status: 'paid'`
    and `payer_userid`, the closest real equivalent to in-person vs. online spend in a
    peer-to-peer wallet with no merchant/online-purchase category.
- **Monthly spending lock** — progress bar comparing this month's spend against the
  existing `spending_alert_amount` notification preference, with a direct link to set
  one if it isn't configured yet.

## 🏛️ Architecture Progress

Compass is read-only and additive: it composes existing endpoints
(`/wallet/balance`, `/transactions/history`, `/payment-requests`,
`/notifications/preferences/current`) rather than adding new ones.

## 💻 Compatibility

iOS · Android · Web · no new backend endpoints or migrations
